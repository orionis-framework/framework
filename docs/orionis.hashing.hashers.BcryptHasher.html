View In Hierarchy

Hash passwords with bcrypt.

Kept for interoperability with existing applications that already store bcrypt hashes.

Concurrency

No locks are used. The backend class and the backend instance are cached on first use: a concurrent first use from several threads may build them twice, and the last write wins. Hashing operations only read that cache, and the fluent setter drops it so later calls rebuild the backend with the new cost factor.
